# v0.3.0 Release Notes

**Release Date:** 2026-08-15

This release adds PDLC (Product Development Lifecycle): a native six-stage lifecycle that becomes the catalog's canonical stage-ID hub, letting other lifecycle and posture frameworks crosswalk through it instead of needing pairwise mappings.

## Highlights

- PDLC splits each of AIDLC's three phases into two parallel lenses — **product** and **builder** — so every stage has exactly one accountable role
- Generic `FrameworkRelation`/`StageCrosswalk` types make PDLC's AIDLC crosswalk (and any future framework's crosswalk) a shared, machine-readable shape instead of a bespoke pairwise mapping
- Full MkDocs site coverage: new PDLC framework page, updated Frameworks Overview, and Go Module API reference entries

## What's New

### PDLC Framework

```go
import frameworks "github.com/ProductBuildersHQ/productbuildershq-frameworks"

pdlc := frameworks.MustPDLC()
fmt.Printf("PDLC: %d phases\n", len(pdlc.Phases))
for _, p := range pdlc.Phases {
    fmt.Printf("  %s (%s, %s)\n", p.Name, p.Role, p.AIDLCPhase)
}
```

Six stages, each with a single accountable role:

| Stage | Role | AIDLC Phase | Gate |
|-------|------|--------------|------|
| Product Definition | Product | Inception | Baseline Approval |
| Builder Definition | Builder | Inception | Technical Design Review |
| Implementation | Builder | Construction | Code Review / CI Gate |
| Deployment | Builder | Construction | Release Gate |
| Builder Operations | Builder | Operation (parallel) | — |
| Product Operations | Product | Operation (parallel) | Baseline Revision Trigger |

Product Definition's seven detailed sub-stages (Discovery through Baseline & Handoff) remain normatively owned by the [pdlc repository](https://github.com/ProductBuildersHQ/pdlc) — this catalog entry is intentionally the coarse six-stage view. New accessors: `PDLC()`, `MustPDLC()`, `PDLCJSON()`.

See the [PDLC framework page](../frameworks/pdlc/index.md) for the full stage-by-stage guide, the AIDLC crosswalk table, and the relationship to Threat Model Spec's ASPM security-posture overlay.

### Generic Crosswalk Types

```go
type FrameworkRelation struct {
    Framework    string           `json:"framework,omitempty"`
    Relationship string           `json:"relationship,omitempty"`
    StageMapping []StageCrosswalk `json:"stageMapping,omitempty"`
}

type StageCrosswalk struct {
    Stage  string   `json:"stage,omitempty"`
    MapsTo []string `json:"mapsTo,omitempty"`
}
```

Not specific to PDLC — any cataloged framework can declare a `RelatedFrameworks` field using these types to crosswalk against another framework without a bespoke mapping type.
